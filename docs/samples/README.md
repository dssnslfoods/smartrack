# เอกสารตัวอย่างสำหรับทดสอบการสแกน

ไฟล์ในโฟลเดอร์นี้เป็น **เอกสารสมมติสำหรับทดสอบระบบเท่านั้น** ไม่ใช่เอกสารทางการค้าจริง
บริษัท ลูกค้า เลขที่เอกสาร และเลขประจำตัวผู้เสียภาษี เป็นข้อมูลสมมติทั้งหมด

| ไฟล์ | ใช้ทดสอบอะไร |
|---|---|
| `sample-delivery-note.html` / `.pdf` | สแกนใบส่งของ (รับเข้า/GRN) — หน้า รับเข้า → 📷 สแกนใบส่งของด้วย AI |
| `sample-purchase-order.html` / `.pdf` | สแกนใบสั่งซื้อ PO (รับเข้า/GRN) — หน้า รับเข้า → 📷 สแกนใบส่งของด้วย AI |
| `sample-pickup-order.html` / `.pdf` | สแกนใบสั่งขาย (วางแผนหยิบ) — หน้า วางแผนหยิบสินค้า → 📷 สแกนใบสั่งขายด้วย AI |

## วิธีทดสอบ

**ใบส่งของ / ใบสั่งซื้อ PO (รับเข้า):**
1. เปิดหน้า **รับเข้า (GRN)** → กดปุ่มสแกนเอกสาร → เลือก `sample-delivery-note.pdf` หรือ `sample-purchase-order.pdf`

**ใบสั่งขาย (วางแผนหยิบ):**
1. เปิดหน้า **วางแผนหยิบสินค้า** → กด **📎 แนบไฟล์** ในการ์ด "สแกนใบสั่งขายด้วย AI"
2. เลือก `sample-pickup-order.pdf`
3. ระบบจะเติมเลขที่ SO + ลูกค้า และเพิ่มสินค้าที่จับคู่ได้เข้าใบสั่งพร้อมคำนวณตำแหน่งหยิบ (FEFO) ให้อัตโนมัติ

ทั้งสองกรณี AI เติมข้อมูลให้ตรวจเท่านั้น — **ต้องกดยืนยันเองเสมอ** AI บันทึกข้อมูลแทนไม่ได้

## กับดักที่ตั้งใจใส่ไว้ในเอกสาร

### sample-delivery-note.pdf (ใบส่งของ)

| # | กับดัก | ควรได้ผลว่า |
|---|---|---|
| 1 | วันที่เป็น **พ.ศ.** (12 กันยายน 2569) | แปลงเป็น ค.ศ. `2026-09-12` |
| 2 | จำนวนมี **ลูกน้ำ** (1,200 · 10,000 · 2,880) | ตัดลูกน้ำออกเป็นตัวเลขล้วน |
| 3 | บรรทัด 6 เป็น**บรรจุภัณฑ์ ไม่มีวันหมดอายุ** | ขึ้นเตือน + ติดธง `needs_review` |
| 4 | บรรทัด 9 เป็น**สินค้าที่ไม่มีในระบบ** (`FG-MSK-CLY80`) | จับคู่ไม่ได้ + ขึ้นเตือนให้เลือกสินค้าเอง |
| 5 | มีทั้ง FG · PK · RM คละกัน | จับคู่ได้ถูกทุกประเภท |

**ผลทดสอบล่าสุด:** อ่านได้ครบ 10 บรรทัด · จับคู่สินค้าได้ 9 · ต้องตรวจ 2 · ใช้เวลาประมาณ 38 วินาที

### sample-purchase-order.pdf (ใบสั่งซื้อ PO)

เอกสารนี้ใช้รหัสวัตถุดิบ/บรรจุภัณฑ์ (RM/PK) แทน FG เพราะ PO สั่งจากซัพพลายเออร์ภายนอก
มักเป็นวัตถุดิบหรือบรรจุภัณฑ์ ไม่ใช่สินค้าสำเร็จรูปที่ผลิตเอง

| # | กับดัก | ควรได้ผลว่า |
|---|---|---|
| 1 | **รหัสสินค้าบนเอกสารเป็นรหัสของผู้ขาย** (`RM-TNK-EXT25`, `PK-BTL-CL300` ฯลฯ) ไม่ตรงกับรหัสในระบบเลยสักตัว | จับคู่จาก**ชื่อสินค้า**ทั้งหมด ไม่ใช่จากรหัส |
| 2 | จำนวนมี**ลูกน้ำ** (5,000 · 8,000 · 6,000) | ตัดลูกน้ำออกเป็นตัวเลขล้วน |
| 3 | **เป็น PO ไม่มีเลข Lot/วันหมดอายุเลยสักบรรทัด** (จะออกตอนส่งของจริง) | เตือนว่าเป็น PO ไม่มี Lot/EXP + ติดธง `needs_review` ทุกบรรทัด |
| 4 | รายการที่ 6 เป็น**วัตถุดิบใหม่ที่ยังไม่มีในระบบ** (กลีเซอรีนจากพืช) | จับคู่ไม่ได้ + ระบุเหตุผลในหมายเหตุ — **ไม่มั่วจับคู่ให้** |
| 5 | มีคอลัมน์ราคา/ภาษี/รวมเงินปนอยู่ (ข้อมูลที่ไม่เกี่ยวกับรับเข้า) | ไม่หยิบราคามาปนกับจำนวนที่รับเข้า |
| 6 | วันที่เป็น พ.ศ. (25 สิงหาคม 2569) | แปลงเป็น ค.ศ. `2026-08-25` |

**ผลทดสอบล่าสุด (1 ก.ย. 2569):** อ่านครบ 6 บรรทัด · จับคู่สินค้าได้ **5/5 ตัวที่มีในระบบ** ถูกทุกตัวจากชื่อ แม้รหัสบนเอกสารจะไม่ตรงกับระบบแม้แต่ตัวเดียว · วัตถุดิบใหม่ (รายการ 6) ถูกปฏิเสธไม่ให้จับคู่มั่ว · ระบบเตือนถูกต้องว่า *"เอกสารนี้เป็นใบสั่งซื้อ (PO) ไม่มีระบุเลข Lot และวันหมดอายุ"* — เป็นเส้นทางเตือนที่ต่างจาก `sample-delivery-note.pdf` (ซึ่งมี Lot/EXP อยู่แล้วบางส่วน)

### sample-pickup-order.pdf (ใบสั่งขาย)

| # | กับดัก | ควรได้ผลว่า |
|---|---|---|
| 1 | **รหัสสินค้าบนเอกสารเป็นรหัสลูกค้าเอง** (BTW-1001, CRM-2003 ฯลฯ) ไม่ตรงกับรหัสในระบบ | จับคู่จาก**ชื่อสินค้า**แทน ไม่ใช่จากรหัส |
| 2 | จำนวนมี**ลูกน้ำ** (1,200) | ตัดลูกน้ำออกเป็นตัวเลขล้วน |
| 3 | **หมายเหตุเขียนมือ** สีฟ้าปนในตาราง (Lot, "เช็คแล้ว 1/9" ฯลฯ) | อ่านได้เท่าที่อ่านออก + เตือนว่ามีลายมือ |
| 4 | รายการที่ 7 เป็น**สินค้าใหม่ที่ยังไม่มีในระบบ** (เจลล้างหน้าทานาคา) | จับคู่ไม่ได้ + ติดธง `needs_review` — **ไม่มั่วจับคู่ให้** |
| 5 | วันที่เป็น พ.ศ. (1 กันยายน 2569) | แปลงเป็น ค.ศ. `2026-09-01` |

**ผลทดสอบล่าสุด (1 ก.ย. 2569):** อ่านครบ 7 บรรทัด · จับคู่สินค้าได้ **6/6 ตัวที่มีในระบบ** ถูกทุกตัวจากชื่อ (ไม่ใช่จากรหัส) · รายการที่ 7 (สินค้าใหม่) ถูกปฏิเสธไม่ให้จับคู่มั่วตามที่ตั้งใจ · เลขที่ SO และลูกค้าอ่านถูกต้อง

## สร้าง PDF ใหม่หลังแก้ HTML

```bash
cd docs/samples && "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="sample-delivery-note.pdf" "file://$PWD/sample-delivery-note.html"
```

เปลี่ยนชื่อไฟล์ตามต้องการสำหรับ `sample-pickup-order.html`
