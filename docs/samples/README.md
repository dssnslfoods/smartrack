# เอกสารตัวอย่างสำหรับทดสอบการสแกน

ไฟล์ในโฟลเดอร์นี้เป็น **เอกสารสมมติสำหรับทดสอบระบบเท่านั้น** ไม่ใช่เอกสารทางการค้าจริง
บริษัทผู้ส่ง เลขที่เอกสาร และเลขประจำตัวผู้เสียภาษี เป็นข้อมูลสมมติทั้งหมด

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `sample-delivery-note.html` | ต้นฉบับ แก้ไขได้ แล้วสร้าง PDF ใหม่ |
| `sample-delivery-note.pdf` | ไฟล์ที่ใช้ทดสอบจริง — อัปโหลดในหน้า รับเข้า (GRN) |

## วิธีทดสอบ

1. เปิดหน้า **รับเข้า (GRN)** → กดปุ่มสแกนเอกสาร
2. เลือกไฟล์ `sample-delivery-note.pdf`
3. ระบบจะอ่านแล้วเติมรายการให้ตรวจ — **ต้องกดยืนยันเองเสมอ AI บันทึกแทนไม่ได้**

## กับดักที่ตั้งใจใส่ไว้ในเอกสาร

เอกสารนี้ออกแบบให้ทดสอบกฎที่เขียนไว้ใน `server/services/ai.js` ครบทุกข้อ

| # | กับดัก | ควรได้ผลว่า |
|---|---|---|
| 1 | วันที่เป็น **พ.ศ.** (12 กันยายน 2569) | แปลงเป็น ค.ศ. `2026-09-12` |
| 2 | จำนวนมี **ลูกน้ำ** (1,200 · 10,000 · 2,880) | ตัดลูกน้ำออกเป็นตัวเลขล้วน |
| 3 | บรรทัด 6 เป็น**บรรจุภัณฑ์ ไม่มีวันหมดอายุ** | ขึ้นเตือน + ติดธง `needs_review` |
| 4 | บรรทัด 9 เป็น**สินค้าที่ไม่มีในระบบ** (`FG-MSK-CLY80`) | จับคู่ไม่ได้ + ขึ้นเตือนให้เลือกสินค้าเอง |
| 5 | มีทั้ง FG · PK · RM คละกัน | จับคู่ได้ถูกทุกประเภท |

## ผลทดสอบล่าสุด (31 ส.ค. 2569)

อ่านได้ครบ 10 บรรทัด · จับคู่สินค้าได้ 9 · ต้องตรวจ 2 · ใช้เวลาประมาณ 38 วินาที

- หัวเอกสาร: `PO-2569-0442` · `บริษัท ตัวอย่างซัพพลาย จำกัด (สมมติ)` · `2026-09-12` ✓
- แปลง พ.ศ. ถูกทุกบรรทัด เช่น `01/09/2571` → `2028-09-01` ✓
- ตัดลูกน้ำถูก เช่น `1,200` → `1200` ✓
- จับกับดักได้ทั้ง 2 จุด (ไม่มี EXP · สินค้าใหม่ที่ยังไม่มีในระบบ) ✓

## สร้าง PDF ใหม่หลังแก้ HTML

```bash
cd docs/samples && "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="sample-delivery-note.pdf" "file://$PWD/sample-delivery-note.html"
```
